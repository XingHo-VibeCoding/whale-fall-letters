## 二、今日要掌握：28 天里最大的一个认知改变是什么？

### 2.1 我的回答（原话）

> 没想到 AI 已经强大到这个地步，借助 AI 可以轻松把自己的想法落地。

这句是真话，但**说得太轻**。如果只写到这儿，它听起来像一句客套——毕竟「AI 很强」是 2026 年最不需要验证的结论。

### 2.2 这句话不是我悟出来的，是这六件事逼出来的

| 哪天 | 发生了什么 | 它改掉了我哪个旧习惯 |
|---|---|---|
| Day 5 | 写 `docs/PRD.md`，把「我想要个记书的本子」拆成 **23 条 AC**，每条都能答「是 / 否」 | 从「我想要…」变成「做到哪一步算完成」 |
| Day 6 | 把 `AGENTS.md` 里一条规则，从**命令式**改写成**检查项式**（「别乱提交」→「提交前先列文件清单等确认」） | 规则不是写给自己看的，是写给「另一个人也能执行」的 |
| Day 8 | 把课程给的示例提示词整份改写成项目版（`docs/day8-prompt.md`），还在顶部标出**哪几句后来被推翻了、哪几条永久有效** | 提示词不是一次性消耗品，它有版本、会过期 |
| Day 14 | 找真人做轻量测试。我自己点一百遍都顺，**对方第一次点就卡在「保存了没有反馈」** | 我熟悉自己的作品，所以我永远测不出真问题 |
| Day 25 | 把「发布前该查什么」写成脚本（九条），不再靠我记得 | 检查从「我记得要查」变成「跑一下就查」 |
| Day 28 | 验收官看了我的交付文档，把我 94 打到 83 | 我看了一眼觉得对，陌生人和机器说不对 |

**六件事连起来的结论**：

> 难的从来不是写代码，是把想法说到**能被验证**的程度。
> AI 让「落地」变便宜了，让「说清楚」变贵了——因为说清楚这件事，AI 替不了你。

这就是为什么录屏里我选的那条改写是「页面能打开吧」→「返回 200 且页面里有鲸落书简」。
**它不是我学会的一个命令，是我换掉的那把尺子。**

### 2.3 但另一面更值钱

28 天里我被 AI 骗过至少 5 次，全是同一个方向：**它会把「没做」说成「做了」**。

- `git commit` 报 `nothing to commit, working tree clean`，紧接着 `push` 显示推上去一个新提交——提交其实建好了
- sw 检查脚本报 9/9 全绿，实际第 4 条比对口径错了，把 CRLF 当成内容差异
- 今天验收官抓到：我自己写的验收表里，五个字节数**全是字符数**，结论碰巧对、过程是假的

所以 `AGENTS.md` 第八节第一条我写得最狠：

> **命令的输出不等于事实。** 说「做成了」要验，说「没做成」同样要验——两个方向都会骗人。

**这才是 28 天里最实在的收获**：不是「AI 什么都能做」，而是「AI 什么都能说，所以你得会验」。

## 三、验收官检测：94 → 83，扣的每一分都该扣

### 3.1 怎么做到「自己不当自己的验收官」

附录 J 的规则很硬：验收官**不认识作者**，只拿公网地址和交付文档，不给任何口头解释，还要随机抽 3 项现场复验。

我的做法：开一个全新的 AI 子会话，**只给它公网地址、仓库路径和附录 J 原文**，明令三件事——

1. **禁止读 `journal/`**（那是我自己的日记，不算交付物，不能当证据）
2. **只读不改**（不许碰文件、不许提交）
3. **默认怀疑，能独立复核的才算 PASS**

它没看过前面 27 天的任何对话，也没听过我一句解释。

### 3.2 它抓到的五件事

| # | 它说什么 | 我复验的结果 | 严重度 |
|---|---|---|---|
| 1 | `GET /api/books/book-001` 这条接口**根本不存在**，可 `api-contract.md` 和 `ROLLBACK.md` 都拿它当探针 | 实测返回「未知路径，本服务提供…」——**成立** | 高（救火手册第一步就是错的） |
| 2 | 我把 GitHub Pages 标成「首选」，但那个域名下接口**跨域被拦**（响应无 `access-control-allow-origin`） | 实测确认无 ACAO 头——**成立** | 高 |
| 3 | 第 7 项那五个字节数**是字符数不是字节数** | 用 `Buffer` 重算：55851/61530/118092/30647/17376，我写的全错——**成立** | 中 |
| 4 | 自评总分算错：分项相加是 94，我写了 92 | **成立** | 中 |
| 5 | 线上有脏数据：`活着` 是 `currentPage 200 / totalPages 191`（Day 17 测试残留） | **成立** | 低 |

它还说了三句话，我抄在这里：

- 「**结论碰巧是对的，但过程是编的**——这比结论错更危险，因为一旦被结果验证，就没人再去查方法。」
- 「同一份文档里，前面的结论被后面的自述推翻。」
- 「**写验收表这个动作，把验收表里引用的那次 FINAL 跑废了。**」

### 3.3 第三句话是真的结构性问题

`preflight` 第 8 条判 FINAL（工作区干净）的前提是**没有未提交文件**。
但结营当天必然要产出新文档——验收表、复盘、检查记录。

**验收表一存在，它引用的那次「9/9 全绿、轮次 FINAL」就变成了 DRAFT。**

这不是谁手滑，是顺序问题。正确做法只有一条：**先提交文档，再跑 preflight，用提交后那一轮当证据。**

### 3.4 已经改掉的（当天改，不留过夜）

| # | 改了什么 | 证据 |
|---|---|---|
| 1 | 两处错误的探针命令，换成三条**实测过**的：`GET /api/health`（函数活）/ `GET /api/books`（函数→库通）/ 数 `"is_deleted"` 出现次数（判版本） | 三条当场跑通；5 本 = 5 次 |
| 2 | 第 0 节地址优先级改掉，加「Pages 不能演示接口」的警告 | 实测无 ACAO |
| 3 | 第 5 节字节数改成按字节，并写明「字符数≠字节数」这个坑 | Buffer 重算 |
| 4 | 总分 92 → 94 → 复核后 83，三个数并排列出 | — |
| 5 | 脏数据 PATCH 回 88/191（≈46%） | 复验通过 |

**我没改的**：83 这个分。它不是我给的，是复核出来的，改它就是作弊。

## 四、核心流程重复检测：两层，各两轮

### 4.1 为什么不能混着测

这个项目有**两条独立的存储链**，混着测等于骗自己：

| 层 | 存哪 | 「刷新」是什么 | 谁跑 |
|---|---|---|---|
| 前端 | `localStorage`（日常书单走这条） | 丢掉整个 JS 环境、只留 localStorage、重新加载 `store.js` | `tests/repeat-check.js`（在仓库里） |
| 接口 | PostgreSQL | 重新发一次 HTTP 请求 | 本节第 4.3 |

### 4.2 前端层：31 个断言 × 2 轮，零失败

新写了 `tests/repeat-check.js`（229 行、零依赖、**放进仓库**，任何人 clone 下来就能跑）。
「刷新」用 `vm.createContext()` 重建上下文模拟——上一轮的 `Store` 实例、内存变量全丢，只把 localStorage 带过去，**跟 F5 的语义一致**。

结果：`共 31 个断言 ｜ 通过 31 ｜ 失败 0`，两轮 14 步**零差异**，最终存储在抹掉 id 与时间戳后完全相同。
连续跑 3 次（合计 6 轮），退出码 `0 0 0`。

### 4.3 接口层：7 步 × 2 轮，全一致

```
第 1 轮  POST 0.506s → GET 6 本 → PATCH 0.408s → GET reading/42/startedAt
         → DELETE {deletedBooks:1, softDeleted:true} → GET gone,5 → 重复删报"不存在"
第 2 轮  POST 0.484s → GET 6 本 → PATCH 0.345s → GET reading/42/startedAt
         → DELETE {deletedBooks:1, softDeleted:true} → GET gone,5 → 重复删报"不存在"
跑前 5 本，跑后 5 本，无残留
```

第 7 步「重复删除」是故意加的：**只测「删除成功」，「删两次都返回 1 条」这种谎报永远测不出来。**

### 4.4 两轮都红 = 断言写错了，不是代码有 bug

第一次跑，两轮**都红在同一步**：`刷新后：书已消失`。

查 `store.js:227` 的注释：

```js
/** 按 id 取一本书。找不到返回 data:null（不是错误）。 */
```

**是我的断言写错了**（我以为找不到 = `ok:false`）。

这件事的价值在信号本身：**两轮红得一模一样，说明这是稳定行为，不是偶发故障。**
如果我当时顺着「红」去改 `store.js`，就把一个正常设计改坏了——**误报和漏报一样坏。**

顺手记一笔技术债：同一个「书不存在」，前端返回 `{ok:true, data:null}`，后端返回 `{ok:false, error:"…"}`。
两边各有道理，但**同一项目两套表达**，将来接真库时一定有人写错一次。今天不改（改前端语义会牵动好几条 AC）。
