## 5. 两处线上与本地一致性比对（去 CR 口径）

Git 存的 blob 是 LF，Windows 工作区是 CRLF，**直接比字节会假红**（Day 26 踩过，今天又踩了一次）。正确做法是去掉 `\r` 再比**字节数**：

| 文件 | 本地原始字节 | CR 个数 | 本地去 CR 字节 | GitHub Pages | CloudBase 静态托管 | 结论 |
|---|---|---|---|---|---|---|
| index.html | 56793 | 942 | **55851** | 55851 | 55851 | 三处一致 |
| styles.css | 62766 | 1236 | **61530** | 61530 | 61530 | 三处一致 |
| community.js | 121084 | 2992 | **118092** | 118092 | 118092 | 三处一致 |
| app.js | 30647 | 0 | **30647** | 30647 | 30647 | 三处一致 |
| store.js | 17376 | 0 | **17376** | 17376 | 17376 | 三处一致 |

> ⚠️ **这五个数字今天改过一次，原因值得记住**：初评写的是 51269 / 57179 / 98356 / 25930 / 14540，那是用 JS 读成字符串后取 `.length` —— **字符数，不是字节数**。一个汉字在 UTF-8 里占 3 字节、在 JS 字符串里算 1 个字符，所以含中文的文件字符数远小于字节数（`community.js` 差 19736）。
> 结论没错（两边确实一致），但**过程是错的口径**，而错的口径恰好得出了正确的结论 —— 这种「结论对、过程假」比结论错更危险，因为它一旦被结果验证，就不会再有人去查方法。
> 正确做法：用 `Buffer` 读，按**字节**比，或者 `readFileSync(f).length`（Buffer 的 length 是字节数）。

| 风险 | 说明 |

## 9. 一条最有效的改写提示词（定稿）

### 改的是什么

|  | 内容 |
|---|---|
| **改之前（不可用）** | 页面能打开吧？ |
| **改之后（可验证）** | `curl -I <网址>` 返回 `HTTP 200`，且 body 里有「鲸落书简」四个字 |

### 为什么是这一条

1. **门槛最低**：一条 curl，不用装环境、不用 clone 仓库、不用跑脚本。发给任何人都能复现——**能被独立复核，才叫证据**。
2. **它把「我觉得」变成「机器说是」**：「页面能打开」是观感，同一句话两个人能得出相反结论；「返回 200 且含这四个字」只能有一个答案。
3. **失败时能定位**：不是 200，说明是部署问题；是 200 但没有那四个字，说明是**打开了别的东西**（比如登录页、404 页、别人的页面）——这一条今天真救过场，见下面。

### 今天实际跑的结果（2026-10-26 20:31）

```bash
curl -sS --ssl-no-revoke -I https://xingho-vibecoding.github.io/whale-fall-letters/
#   HTTP/1.1 200 Connection Established   ← 这是代理隧道，不是网站状态，别当结果
#   HTTP/1.1 200 OK                       ← 这一行才是

curl -sS --ssl-no-revoke https://xingho-vibecoding.github.io/whale-fall-letters/ | grep -c 鲸落书简
#   3
```

CloudBase 地址同样：`200 OK` + `鲸落书简` 出现 3 次。**两个地址都过。**

### 这条改写真正的价值

不是学会了一个命令。是改掉了「什么时候算做完」的标准：

- 改之前：我看了一眼，页面出来了 → 算完
- 改之后：状态码和内容都对上 → 才算完

**28 天里这一句最值钱**，因为它能套到后面每一件事上：接口是不是活着、静态托管是不是最新版、录屏里说的数字是不是真的。
今天上午验收官把我 94 分打到 83 分，扣的全是「数字没复核」——用的就是这条标准反过来查我。
