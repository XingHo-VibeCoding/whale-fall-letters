## 七、写这个 Skill 时自己踩的五个坑（都比检查项本身更值钱）

1. **`curl -w` 漏写 `%{http_code}`** → 状态码永远解析成 0。接口明明 200 返回了 5 本书，第 5 条却报「连不上」。**教训：检查报红时，先怀疑检查自己瞎了。**
2. **该先抢 id 再判状态，写反了** → 第 6 条状态一失败就 `return`，临时书 id 还没存下来，`finally` 没东西可删，**真库真留了两本 `preflight-*`**（已全部清掉，复查 5 本、残留 0）。
3. **拿「应该 404」当判定依据** → 这个接口的业务失败一律 HTTP 200 + `{ok:false, error}`（`send()` 里固定 `writeHead(200)`）。接口明明回了「这本书不存在」，被判成 FAIL。**判业务结果看 `ok` 字段，不看状态码。**
4. **`sk-` 正则漏了连字符** → 见第三节，真实格式 `sk-live-*` 完全不命中。
5. **文档里的演示密钥把检查自己扫红** → 这份记录和 `SKILL.md` 里为讲清「怎么故意弄坏」写了示例密钥，提交后跑 FINAL 轮会被第 1 条当成真泄露。已给规则加占位符跳过（连续 `X`、`REDACTED`、`EXAMPLE`、`…`），文档里的演示值统一写成 `sk-live-XXXX…`。

五条都已写进 `SKILL.md` 第五节。

## 八、发现但今天没修（记下来，不顺手改）

1. **第 4 条的字节比对会被行尾干扰**：工作区 CRLF、仓库 LF，`git checkout` 后 `wc -c` 会变（`db.js` 10357 → 10584）。今天五个前端文件刚好全等，没触发；但换个环境编辑就可能假红。修法是以「去 CR 后的哈希」为准、字节数只作证据 —— 今天不动。
2. **接口用 HTTP 200 返回业务失败**（`{ok:false, error}`），对 curl / 第三方调用方不友好。这是 Day 19 定的契约，改它就是改契约，要单独讨论。
3. **`.env` 靠 `*.env` 宽规则兜底**：能挡住文件，但以后加 `.env.local`、`.env.production` 会被一起挡掉，容易看不懂为什么没生效。建议补一条显式 `.env`。
4. **连点「刷新」仍无并发保护**（Day 24 记过，今天未动）。
