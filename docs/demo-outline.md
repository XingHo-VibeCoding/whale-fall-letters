# 演示提纲（Day 21）

> 用于下周对群/对组织的 3 分钟演示。四段结构固定：用户问题 → 核心流程 → 提示词改写 → 验证方式。
> 演示环境：CloudBase 静态站 <https://reading-sea-d7gd8l7o78b7304ae-1385227197.tcloudbaseapp.com/>

---

## 第一段：用户问题（为什么要做这个）

> **场景**：大帅在手机上看到一本书想读，想记下来，但电子书软件里只能做书签，不能“标记状态 / 记页码 / 写笔记 / 再找回来”；现有阅读 App 数据各自为政，跨设备也不方便。
>
> **痛点（三行）**：
> 1. 没有一个地方把“书 / 进度 / 笔记”三件事绑在一起记；
> 2. 手机上打开网页应用，按钮点下去没反应，用户以为没保存；
> 3. 关掉页面再打开，数据是不是还在，用户不敢赌。

> **一句话拍板**：本站做一件事——手机/电脑都能打开的读书记录本，记书、记进度、记笔记，刷新不丢。

---

## 第二段：核心流程（现场走一遍）

> 演示链路（全部在手机上演，耗时约 90 秒）：

| 步骤 | 操作 | 预期现象 |
| --- | --- | --- |
| 1 | 打开 CloudBase 链接 | 深蓝紫底书架页，标题「鲸落书简」，中间「添加第一本书」 |
| 2 | 点「添加书籍」，填书名「测试书」、作者「阿澈」，点保存 | 弹窗关闭，卡片立刻出现在列表，标签「想读」 |
| 3 | 点卡片进详情，下滑到笔记区写「第一条笔记」保存 | 笔记出现在列表最上方 |
| 4 | 填「当前第几页：100」，总页数「300」，点保存 | 显示「第 100 / 300 页」＋「33%」 |
| 5 | 按手机返回/刷新 | 书、笔记、进度全部还在，页面没变白 |
| 6 | 点导航「接口数据」 | 表格里出现 5 本真书，下面有「最后更新」时间戳 |

> **现场反差点（故意给对比）**：演示「不填书名直接保存」——弹窗不关、不产生空记录，有提示。这是 AC-2，验「不是什么都能乱存」。

## 第三段：提示词改写（把模糊的说成可验证的）

> 演示前先说一句：我们不演“感觉上挺好的”，只演“能被独立复核的”。

| 模糊说法（不可用） | 提示词改写（可验证） | 对应证据 |
| --- | --- | --- |
| 页面能打开吧？ | `curl -I <网址>` 返回 `HTTP 200`，且 body 含「鲸落书简」 | `day21-verify/pages-root.html`（55 854 字节） |
| 能读能写吧？ | POST 一本新书 → 返回 `ok:true` + 真实 `id` + `createdAt`；再 GET 列表里能搜到这本 | `day19-verify/live-05-post-success.json` → `live-06-get-after.json` |
| 刷新不丢数据吧？ | 脚本跑完 `通过 81 项，失败 0 项`，其中「刷新页面：数据还在」4 项全绿 | `_d2d_test.js`（81 项断言） |
| 别人能打开吧？ | 陈迎昕手机远程操作，6 条回答：是 / 是 / ok / 在 / 有 / 没有 | `docs/user-tests/Day-21-peer.md` 第二节 |

> **对群/对组织说的那句话**：「我们不说‘大概可以’，只说‘我刚刚用 curl 跑了一遍，状态码是 200，数据在公网上，另一个人在手机上也跑通了』。」


```bash

# 预期：200，body 是 5 本真书
```
