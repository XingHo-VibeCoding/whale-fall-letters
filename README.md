# 鲸落书简 · whale-fall-letters

> 记录你的阅读，也遇见读同一本书的人 —— 让你遨游在书籍的海洋里。

## 这是什么

一个纯前端的网站项目：**记录自己的书单、阅读进度和读书笔记**，并在 Day 11 起升级为**公开的阅读交流社区**——注册账号后，可以把正在读的书分享到论坛、写下感受，和其他读同一本书的人交流、私信。

**它始终不提供任何书籍正文。** 只做「记录」和「围绕书的讨论」。这条边界来自需求研究（见 [`docs/research.md`](docs/research.md)），其中「不做社交」一条已在 Day 11 因新需求放开——改动理由和新的完整蓝图见 [`docs/COMMUNITY_DESIGN.md`](docs/COMMUNITY_DESIGN.md)。

项目目前处于**学习期**：一边按日程学 Git 和前端，一边把学到的东西落进这个仓库。书单 / 进度 / 笔记三个功能 Day 7 已经做好；社区功能的前端界面 Day 11 做好，但数据还只存在浏览器内存里——打开就能用，怎么跑见[「运行方式」](#运行方式)。

## 运行方式

纯静态页面，**没有任何依赖，也不需要构建工具**。有三种打开方式，选一种固定用就行。

### 在线版（手机也能开，发给别人就能用）

两个地址都能打开，**同一份代码**。对外给链接、演示接口，用第一个：

| 用途 | 地址 |
|---|---|
| **主用**（国内快、接口能通） | **<https://reading-sea-d7gd8l7o78b7304ae-1385227197.tcloudbaseapp.com>** |
| 备份（GitHub Pages，2026-09-30 开启） | <https://xingho-vibecoding.github.io/whale-fall-letters/> |

> ⚠️ Pages 那个地址**接口功能用不了**：网关的跨域白名单只放行 CloudBase 域名，在 Pages 上点「接口数据」会被浏览器拦掉，报错还容易误读成「网络连不上」。
> 部署与到期说明见下面「[部署、额度、到期与备份](#部署额度到期与备份)」。

> 注意：**书单和笔记存在「打开页面的那台设备」自己的浏览器里**。你手机上记的和电脑上记的**互不相通**。接口那条链（CloudBase 域名下的「接口数据」页）走的是云端数据库，两处数据目前是分开的——把书单整体接到云端，是 v1.0 之后的第一件事。

### 方式一：直接双击（最省事）

在文件管理器里双击 `index.html`，浏览器会以 `file://` 的方式打开它，不需要启动任何服务。

**实测记录（2026-09-25，Windows 11 + Edge）**：双击打开 → 添加一本书 → 按 F5 刷新 → 书**还在**。

但这条路能用，是浏览器给的宽容，**不是标准给的保证**：`file://` 地址下 localStorage 属于**规范未定义行为**（MDN 的 localStorage 文档明确写了「不应依赖」），各浏览器做法不一致。所以：

- 本机现在可用，**换浏览器或换电脑就不一定**（Firefox / Safari 对 `file://` 更严格）
- **无痕 / 隐私窗口下一定存不住**，别在那里记东西
- 数据只在这台电脑的这个浏览器里，**清缓存、重装系统会丢**；重要的笔记自己另存一份

### 方式二：本地服务（更接近线上环境）

在项目目录下执行：

```bash
python -m http.server 8000
```

然后**在这台电脑上**打开浏览器，在地址栏输入 `http://localhost:8000`。

> `localhost` 的意思是「这台电脑自己」——这个地址只在「这台电脑 + 上面的命令正在运行」时才打得开。**手机和其他人的设备访问不了它**，这不是链接坏了，是它本来就只指向本机。

也可以用 `npx serve`，但它需要联网下载工具，校园网环境下不一定顺利——上面的 Python 方式无需联网。

### 三种方式的存储是分开的

`file://`、`http://localhost:8000` 和在线版网址，是**三个不同的来源**，浏览器各存一份数据，互相看不见。本地加的书不会出现在在线版里，反过来也一样——**这不是 bug**，是本来的规则。

> 提示：本地的数据库文件、环境配置不会进仓库，已被 `.gitignore` 挡住。

## 发布前检查

准备推上线、或者要把链接发给别人之前，先跑一遍：

```bash
node skills/pre-release-check/scripts/preflight.js
```

九条自动检查：密钥有没有进仓库、`.env` 有没有被正确忽略、GitHub Pages 能不能打开、**静态托管和本地文件是否一致**、接口是否活着、数据库迁移和代码是否对齐、有没有临时文件混进仓库、是否已全部推送、有没有引外部 CDN。另外两条必须人眼看的（手机宽度观感、键盘操作）**单独列、不算通过**。

```bash
node skills/pre-release-check/scripts/preflight.js --only 1,4      # 只跑指定几条
node skills/pre-release-check/scripts/preflight.js --md docs/skill-runs/xxx.md   # 顺便写一份报告
```

退出码：`0` 全过、`1` 有未通过、`2` 脚本自己崩了（不是项目的问题）。**有红项就不许发。**

两个容易忘的前提：

- **静态托管是手动上传的**，`git push` 不会更新它 —— 所以第 4 条查的是静态托管，不是 Pages。
- 脚本会先看工作区干不干净，自动判 **DRAFT**（还没提交，第 8 条必然红，属预期）还是 **FINAL**（干净，这才是真的发布前状态）。

它只检查、不修东西 —— 红了先报告，确认后再动手。完整的九条清单、判定规则和踩过的坑见 [`skills/pre-release-check/SKILL.md`](skills/pre-release-check/SKILL.md)。

## 技术栈

原生三件套，**刻意不引入框架、构建工具和外部 CDN**（校园网 + 代理环境下，外部资源不可靠）：

- **HTML** —— `index.html` 一个页面装下全部视图，靠 `hidden` 属性切换，不做页面跳转
- **CSS** —— `styles.css`，全部样式集中在这里；不用框架、不用 CDN 字体、不用图标库（图标一律用文字符号）
- **JavaScript** —— 分成三层：`store.js` 是**唯一**读写浏览器存储的地方，`app.js` 管记录层（书单 / 进度 / 笔记），`community.js` 管社区层（账号 / 论坛 / 热门 / 私信）。三个普通 `<script>` 按顺序引入，**不用 ES 模块**（`file://` 下模块请求会被 CORS 拦掉，页面直接白屏）

数据分两份，都还没有上服务器：

- **书单 / 笔记**存在**浏览器本地**（localStorage），只用两个键：`reading:books` 和 `reading:notes`——刷新、重开浏览器都还在。
- **社区数据**（账号、帖子、私信）暂存在**页面内存**里——刷新就清空，等着后端 + 数据库接管。

> 早先为什么选纯前端，以及后续接后端 / 数据库要怎么改，见 [`docs/TECH_DESIGN.md`](docs/TECH_DESIGN.md) 与 [`docs/COMMUNITY_DESIGN.md`](docs/COMMUNITY_DESIGN.md)。

工程方面：

- 版本控制用 **Git**，托管在 **GitHub**
- 推送走 **SSH over 443**（校园网封了 22 端口，已在 `~/.ssh/config` 配好转发）
